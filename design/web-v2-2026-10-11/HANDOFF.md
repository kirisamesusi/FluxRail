# FluxRail 配置网页改版 · 实现交接

给负责接功能的窗口。先读仓库的 `AGENTS.md`、`docs/FluxRail_开发交接_窗口必读.md` 和 `docs/modules/05_Web配置工具.md`，再读本文和 `DESIGN.md`。

## 0. 一句话

把现有 `web/` 的前端换成 `prototype/index.html` 的样子和交互，设备通信、协议、校验、测试沿用原来的，不重造。原型是静态演示，所有「设备」行为都是假的，功能要接到 `web/src/` 现有模块上。

## 1. 原型与现有网页的关系

| 项 | 现有 `web/` | 新设计 |
| --- | --- | --- |
| 导航 | 左侧边栏 8 个模块 | 顶部 3 个页签：设备状态 / 固件 / 实验性功能 |
| 首页 | 设备状态 + 各模块分页 | 按键、灯光、滑轨、旋钮、模板**全部并进设备状态首页** |
| 连接按钮 | 侧边栏 | 顶栏 |

## 2. 要做的改动（按页面）

### 2.1 顶栏

- IO4 开关：**不是即时切换**。沿用原逻辑：选择启动模式 → 属于未保存草稿 → 点「应用并保存」后下次上电生效。启用时弹原文案的确认（第 5 节）。状态文字：连接后读取启动模式 / 已读回：普通模式 / 待应用：IO4 模式。
- 重启设备、连接 / 断开、应用并保存：沿用现有逻辑。未连接时重启、应用并保存、IO4 开关都禁用。

### 2.2 设备面板

- **左旋钮 = 旋钮 1，右旋钮 = 旋钮 2**（用户确认）。界面不再显示 U4 / FPC1 / P1 这类内部名字。
- 旋钮和滑轨各有两个实时指示：原生（蓝）、灵敏度后（粉）。数据来自现有运动遥测（`integration.js`）。`web/src/knob-preview.js` 的本地旋转预览改成：只在测试 / 演示模式下可以用滚轮和拖动，连上真实设备后只跟随硬件。
- 滑轨读数：原生用百分比，灵敏度后用 0–1 的数值。
- 按键「按下」效果：设备真的按下按键时，对应按键下沉并亮蓝色光圈。数据来源是现有输入状态（`input-status` 里的按键状态）。**这和鼠标点选是两个独立的效果，可以同时出现。**
- **删除 PUSH**：Web 里去掉 P1 / P2 按压的按键映射项、「面板布局」说明里关于 P1 / P2 的那句、实验性功能里的「旋钮 · PUSH 防误触」分组、旋钮标题里的 P1 / P2。**底层（固件、协议、schema）先保留不动**，只是网页不再显示和编辑。注意：保存时要原样带回这些字段，别把 PUSH 配置写丢。

### 2.3 按键设置（右栏）

- 按键动作下拉：禁用、鼠标左键 / 右键 / 中键、键盘键；另有「监听按键」按钮（沿用原监听逻辑，Esc 取消）。原来的说明段落「允许重复映射……」用户认为没有意义，已删除，不再显示。原型里没有「启用此按键」开关，用「禁用」动作代替。
- 按键灯光：只在灯效为「自定义」时可编辑（颜色 + 亮度），见 2.5。

### 2.4 旋钮 / 滑轨设置（右栏）

- 旋钮：启用旋钮输入、反转输出方向、输出轴（X / Y）、灵敏度。
- 滑轨：启用滑轨输入、反转输出方向、中心灵敏度。
- 灵敏度控件沿用 `gain-control.js` 的 1.0～10.0 刻度、一位小数、旧配置保留逻辑，只换外观：滑块加「低 / 高」，旁边数字输入。
- 右栏顶部「设备实时读数」框显示原生和灵敏度后两个读数，没有数据时写「暂无有效位置」。

### 2.5 灯光

- 控件：键灯启用、灯效（常亮 / 呼吸 / 同步换色 / 彩虹流动 / 按下即亮 / **自定义**）、亮度、全局颜色。
- **「自定义」灯效 ↔ 现有 `lighting.per_key`**：选「自定义」= `per_key = true`，并让全局颜色不可编辑；选其他灯效 = `per_key = false`。（用户确认保持这个互斥设计。）这样会失去「某种动画灯效 + 逐键颜色」的组合，用户已知并接受。
- 逐键颜色编辑：右栏选中按键后设置（对应 `lighting.key_colors[id]`）。亮度的实现方式（逐键亮度字段是否存在）**需要先核对 `docs/模块1` 和协议**，如果设备端没有逐键亮度，右栏只保留颜色，不要新增协议字段。
- 颜色选择器：三个色球 + 调色盘球，行为见 `DESIGN.md` 第 6 节。三个球的内容属于网页本地的使用习惯，**可以存在浏览器 localStorage**（用 try/catch 包起来），不写进设备。全局颜色和按键颜色各一套。
- 动画周期 ms、动画反向留在实验性功能。
- **主界面不放任何引导去「实验性功能」的文字**：原项目里的「逐键颜色在实验性功能…」「输出范围…」「详细范围与共享校准…」之类提示，主界面一律删除（页签本身保留）。
- **旋钮默认输出轴**：左旋钮默认 X，右旋钮默认 Y（新建模板/默认配置时生效）。
- 右侧检查器已压缩（读数框无标题和说明、灵敏度提示一行），保证看板娘气泡不会盖住旋钮/滑轨的设置项。

### 2.6 模板

- 左栏列表点选 = 在右栏管理，不切换设备。四个预设（SDVX 双旋钮、音击、In Falsus、普通多 K）不能覆盖、不能改名。
- 右栏按钮（沿用原名）：设为活动模板、保存到当前模板（选中预设时变成「新建模板后保存」）、修改名称、删除自定义模板、恢复预置模板。左栏下方「新建模板」。
- **模板名称：1～10 个字符，可以用中文，不含双引号和反斜杠。** 现有规则是 1～31 个 ASCII 字符。要同时核对：协议和固件是否按 UTF-8 存储、字节上限是否仍是 31 字节（10 个中文 = 30 字节，刚好放得下；不要允许 emoji 之类 4 字节字符）。如果固件只收 ASCII，这是一个需要改底层的任务，**先停下来告诉用户，不要在网页里偷偷转码**。
- 使用中的模板不能删除。
- 点选预设会恢复默认设置的现有行为保留。

### 2.7 设备信息

首页左栏一个默认折叠的「设备信息」卡片，七项沿用原来的：设备型号、固件 / 协议、唯一序号、当前 USB 模式、启动模式（设备 RAM）、活动模板、设置修订号。展开时左栏内部滚动，**不能让整个页面变高**。

### 2.8 横幅与气泡

- 横幅三个标签：设备型号、固件版本、活动模板。活动模板要**跟随当前活动模板变化**；如果和设备上已保存的不同，后面加「（未保存）」。
- 气泡的状态、文字、淡出规则见 `DESIGN.md` 第 8 节。
- 看板娘彩蛋：右栏底部键盘插画是按钮，点击在头顶冒气泡、随机一句话，5 秒消失。台词读取 `web/assets/mascot-lines.txt`（需要加入服务器白名单和部署导出，参考原型同目录的 `mascot-lines.txt`）。

## 3. 「改动即时生效」的逻辑（需要你先核对再做）

用户的设计意图：**设置改动立即在设备上生效（设备 RAM），哪怕没点保存；点「应用并保存」才写入 flash。** 问题是这些「已生效但未保存」的改动会被模板切换、重新读取、断电覆盖或丢失。解决办法是把状态分清并在界面上说清楚：

1. 两层状态：**已生效**（设备 RAM）和**已保存**（flash）。界面只提示一件事：「有 N 处修改已生效，还没保存」。
2. 「还原修改」= 让设备回到**上次保存**的设置（读回已保存的配置并应用），不是原来「重新读取设置」的含义（原来那个会保留 RAM 里未保存的设置）。弹窗文案见第 5 节。
3. 以下操作会覆盖或丢失已生效未保存的修改，必须弹确认：切换模板、还原修改、重启设备、断开连接（只提示，断开本身不保存）。
4. 断开后设备**仍在使用**未保存设置，直到断电或重启。断开时的文案要说清这一点。
5. IO4 启动模式不属于「即时生效」，它是下次上电才用的草稿，必须点「应用并保存」。

**需要核对的风险**（请先读 `web/src/device.js`、`workflows.js` 和协议文档，确认后再实现，不要凭本文假设）：

- 现有流程是「网页草稿 → 应用到 RAM → 保存」，有 `expected_revision` 并发保护和 `validateDraft`。即时生效要对每次改动做防抖后调用「应用」，并保证连续拖动滑块不会堆积请求、不会因为 revision 不一致报错。
- 没通过校验的值不能下发。数字输入过程中的中间值（例如只输入了「5.」）不要下发。
- 即时生效有锁死风险：例如把所有按键设成「禁用」。「还原修改」和重启设备必须随时可用，且不依赖已被禁用的按键。
- 如果核对后发现现有协议不适合逐次应用，**保留原来的「网页草稿，点应用才下发」模式**，界面文案改回「有 N 处修改还没应用」，并告诉用户。这个选择由用户定。
