# 公共架构与配置契约

更新：2026-10-06。对应当前整合工程，历史逐字段规格见文末。业务模块已接入，旧稿“建议目录”“尚未接入”“运动能力false”仅是对应阶段记录。

## 所有权和数据流

唯一入口[FluxRail.ino](../firmware/FluxRail/FluxRail.ino)调用[App](../firmware/FluxRail/src/app/App.h)。

| 层 | 所在核心 / 主要入口 | 职责 |
| --- | --- | --- |
| 实时采集 | 核心1：[Acquisition](../firmware/FluxRail/src/app/Acquisition.h)、[InputWorker](../firmware/FluxRail/src/realtime/InputWorker.h) | 十BT、Hall、双SSI/PUSH、滤波/位置/校准；发布边沿、分时运动及低频诊断 |
| 动作和来源 | 核心0：[MotionRouter](../firmware/FluxRail/src/app/MotionRouter.h)、`keyboard/ActionMapper.*` | 十二来源键鼠映射；轴所有者、分段余量/背压/故障恢复 |
| USB | 核心0：[UsbBackend](../firmware/FluxRail/src/usb/UsbBackend.h) | 唯一TinyUSB栈、身份、描述符/回调、NKRO/鼠标/IO4 |
| 配置 | 核心0：[ConfigCoordinator](../firmware/FluxRail/src/app/ConfigCoordinator.h)、`config/` | 完整快照、模板、校验、跨核实际应用ACK、唯一Flash所有者 |
| 交互 | 核心0：`protocol/`、`lighting/` | CDC有界JSON、灯PIO/DMA、维护状态；Web只读写配置和低频遥测 |

当前调度：十BT每500us，Hall完整三ADC每1000us，两SSI各500us；迟到跳过旧周期，只采当前一次。LED约60Hz，采集快照20Hz，网页串行轮询约10Hz。这些是实现节拍，不等于主机/游戏延迟或传感器无漏采证明。

跨核使用SPSC及邮箱，业务模块不直接调用Mouse、Serial、Flash，也不另造Profile或setup/loop。边沿source0..9为BT，source10/11为过滤后的PUSH。高频运动复用模块队列，诊断按值复制，核心0不直接读核心1可变模块对象。

## 配置采用与恢复

[DeviceConfig.h](../firmware/FluxRail/src/common/DeviceConfig.h)是唯一设备配置；[MotionTypes.h](../firmware/FluxRail/src/common/MotionTypes.h)的AcquisitionConfig只是活动模板和全局校准的采集投影。

配置变更：完整校验→PauseApply/核心1暂停发布并ACK→核心0清旧队列/路由、释放及状态重建→实际应用配置、重建参考→Resume ACK→成功应答。输入的revision/epoch/sequence阻止旧配置事件重放；不能只更新核心0就向网页报告生效。

revision是配置修订，epoch是运行流代际，schema是持久化格式，firmware_version是固件发布版本，四者不可混用。USB忙时运动不扣量；提交成功才消费，提交不代表游戏收到。断连、队列故障与维护恢复清历史，按当前真实状态重建。

来源策略：X在有效Hall和X旋钮间按物理活动接管，当前活动源保持，达到idle_us后允许其他活动源；同时起动按simultaneous_hall_first。双旋钮同轴先动者持有，同批编号0优先；Y独立。背景旋钮增量明确丢弃并计量，不积到下次补发。正反分段保序，同方向相邻可合并，不跨反转抵消；容量有限，溢出触发账本和恢复。

普通报告、易失XY及IO4协议详见[USB模块](modules/02_USB与IO4.md)，滑轨/旋钮语义不得在路由层混为同一种积分。

## 模板与Flash schema2

四预置ID1～4，初始活动4；自定义最多8，总12。预置不能删，可改名/参数及恢复；稳定ID从5递增、不复用。设备名1..31可打印ASCII（排除引号、反斜杠），页面中文标签不改变设备格式。每模板包含十二普通绑定、独立十二IO4功能表、消抖/灯/指示、Hall与两旋钮及PUSH设置、来源策略。校准及generation、启动USB身份为全局。

这里描述固件接口能力。当前Web产品流程保护预置：点击预置恢复其默认RAM值，保存编辑内容时创建自定义副本，UI不直接改名/覆盖预置；自定义模板选择只读回、不自动激活。接手时区分后端支持能力与当前页面策略，详见Web模块。

选择编辑模板、激活模板、RAM应用、显式save是不同动作。所有成功变更推进revision；RAM预览/切模板/恢复预置不自动写Flash。保存完整已确认DeviceConfig，不另写一个EEPROM身份字节。

逐字段小端序编码，禁止直接写C++结构体/padding。schema1旧格式只读迁移，保留ID、设置和全局校准，补齐IO4功能表；下次显式save写schema2。未知schema、header/payload不一致、非法值/CRC/长度拒绝。schema2每Profile341B，初始四模板无校准payload1387B，金样CRC1053904252；金样不是用户当前配置CRC。

两独立8192B槽：256B header、最多7680B payload、末256B commit。擦非当前有效槽，写header/payload→逐字节与语义读回→最后commit→完整读回。旧槽保留；启动选合法新generation，坏槽退回另一槽，两槽均坏回默认且dirty，不自动擦写。精确magic/字段顺序与迁移见[存储冻结稿](archive/2026-10-05/spec/12_完整配置与Flash序列化.md)、[IO4 schema2](archive/2026-10-05/spec/13_IO4软件契约.md)及[DeviceCodec.cpp](../firmware/FluxRail/src/config/DeviceCodec.cpp)。改字节格式需新增schema和显式迁移。

## Web灵敏度标尺（2026-10-06）

用户要求滑轨和两旋钮统一1.0～10.0、步进0.1，5.0保持原实际倍率1；数值越小响应越低、越大越高。产品标尺采用线性换算 `实际gain = 灵敏度 / 5`：1.0→0.2倍、4.9→0.98倍、5.0→1倍、5.1→1.02倍、10.0→2倍。换算只在Web明确编辑时进行，完整草稿、CDC及schema1/2快照仍存旧单位的实际gain；没有重定义字段、增加schema或更改固件默认实际gain1。新1.0～10.0的全部91个值都落在现有Hall0.1～8和旋钮0.01～16的合法实际倍率范围内，不向旧固件发送gain10冒充新刻度10。

一位小数用于产品标尺输入与显示，不截断底层实际倍率或算法结果。后续按用户要求，数字框在键入/粘贴时就只保留最多一位小数（5.19→5.1），不等失焦后舍入；保留小数点、删除/替换及箭头0.1编辑，禁止科学计数法和正负号。完成编辑时仍校验1.0～10.0，10.1等越界输入拒绝而不夹紧。设备读回不量化或标脏；Hall f32只容忍表示误差。旧配置若超出新标尺或无法准确表示到0.1，控件空置并明确显示旧实际倍率、保留提示，尺上隐藏拇指；无关字段保存仍保留原值，只有明确选择新灵敏度才替换。旋钮物理原始圈数、活动阈值、校准每通道gain和counts_per_turn_at_gain1单位都不变，后者在Web标为“灵敏度5.0每圈 HID count”。

实现见 [sensitivity.js](../web/src/sensitivity.js)、[gain-control.js](../web/src/gain-control.js)，验证及Luna评审见 [本轮记录](../web/tests/sensitivity-2026-10-06/README.md)。真实运动手感、最终硬件和游戏仍须验收。本轮没有重新编译正式固件或连接真实设备。

## CDC、维护和校准

唯一命令表：[CDC_PROTOCOL.md](../firmware/FluxRail/src/protocol/CDC_PROTOCOL.md)，CDC v1 / scope=device_schema2。JSON行4096B、384 token、12层限制；每轮RX128/TX64预算，请求应答轮询，无第二套实时协议。生产客户端应答超时后关闭端口并重新握手；未知写入结果先读回，不盲重试。第三方客户端停止读且不关闭时，TX可能持续等待，这项残留限制尚在。

save/USB冷重启/进入UF2复用维护：暂停ACK→清旧流/释放键鼠→确认USB实际完成与LED DMA结束→工作→重建/Resume ACK。faulted但仍busy的灯不能视为DMA结束。Flash关中断/暂停另一核是明确维护停顿；不承诺此期间实时输入。

校准start先全局握手，随后只抑制Hall，其他来源继续。空场、三参考、7～17实际毫米标签、映射检查、全轨扫、finish；人工标记需依据实际安装。失败/取消保留旧校准；成功实际采用后更新唯一配置revision/generation，仍仅RAM，显式save才持久化。校准期间拒绝普通配置/保存/冷重启；只读诊断及任务命令仍可用。

合法配置被异步永久拒绝时可能持续恢复重试，目前无合法配置可复现实例；后续真实故障注入应检查。公开完整路由原因遥测/benchmark尚未加入，内部账本和ARM测试已存在。
