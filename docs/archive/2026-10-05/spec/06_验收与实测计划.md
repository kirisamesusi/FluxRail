# FluxRail 验收与实测计划

版本：v0.4 · 更新：2026-10-03。需求编号以[用户版主需求](../handoffs/FluxRail_需求总览_用户版.md)为准，未决项目见[决策清单](08_功能缺口与使用场景清单.md)。**模块1及既有公共层已有严格编译、ARM指令模拟和正式ELF描述符验证，当前证据见[模块1进度](../progress/模块1.md)。本文件用例是验收计划；实板、USB主机和游戏验收尚未执行，模拟不替代这些验收。**

## 1. 记录方式与前置检查

每份结果记录需求编号、日期、固件/依赖/配置版本、板型、机械安装、主机系统、游戏版本/输入路径、步骤、预期/实测及异常日志。分别标记未测/模拟通过/编译通过/实板通过/游戏通过；旧板历史记录不能充当新板结果。

开工前复核GPIO/FPC与CN异号脚序、Flash配置、逐灯索引，测磁铁中心行程与高度/极向。冻结公共数据/队列/协议、存储区和待验证USB报告方案。实板先检电源/启动/USB/每键/每灯/三ADC/两SSI及PUSH原始信号，再调手感。

## 6. 来源路由与USB专项（P01、U01/U02）

滑轨→X旋钮→滑轨、背景来源运动、两者同时起动/持续动作/短暂停顿：按D11/D12冻结规则，无采样级互抢；旋钮不补历史，滑轨回到当前固定绝对位置。Y及鼠标按钮不被接管清空。

普通和IO4分别检完整描述符/长字符串/端点/初始化。IO4核对control SET_REPORT与interrupt OUT形态、开关/Side极性、ADC中心/方向；记录主机是否真实打开设备，hook仿真成功不能代替原生设备成功。

单固件双向冷切换：保存启动身份→释放/断开→重启→首次即正确枚举；不靠重刷/临时拔插恢复。IO4无CDC时实测物理返回普通模式入口。建议普通/IO4各冷上电≥20次、双向切换≥50轮作为压力起点，次数不是用户已承诺指标。完整审核见[09](09_IO4兼容与USB冷切换.md)、[10](10_IO4外部项目对比.md)。

## 7. 性能目标与证据

“静止稳、顺滑、跟手、激烈操作不丢帧”是Q01要求；下表数值为待实测起点，未承诺通过。

| 项目 | 起始建议 | 应记录 |
| --- | --- | --- |
| 按键 | 0.5～1ms扫描；正常最大间隔目标≤2ms | 电平/消抖/稳定边沿/成功提交的分段延迟 |
| 霍尔 / SSI | 三向量1kHz；每旋钮2kHz | 最大采样/有效间隔、超期、CRC/场状态，不只平均频率 |
| USB | 实时端点请求1ms；键稳定后大多数提交目标≤2ms | 主机实际报告节奏、最长积压；bInterval不是总延迟证据 |
| 运动 | 额外滤波延迟起点≤2～4ms | 外部动作参考和快反向，不用网页估算 |
| 静止 | 关键位置各10秒；旋钮目标0累计漂移 | 滑轨峰峰值/重复到位误差、旋钮漂移与最小动作响应的取舍 |
| 并发 | 至少5分钟压力起点 | 队列/有效间隔/CRC、灯/CDC/诊断开关对照、资源峰值 |

滑轨慢移建议每方向≥3次、快扫/反向≥20组供重复比较；最终容差和次数依据装配/游戏共同确定。

“不丢帧”分开核对采样、有效信号、HID发送和主机/游戏接收。每旋钮每轴：有效产生≈成功提交+未发余量+明确策略丢弃；绝对滑轨检时间序列/最新坐标/误差，不能把绝对值相加。快速正反总和为零不证明过程正确；不能因长阻塞把整段来回抹掉。

压力组合：十键交替+滑轨快扫+双旋钮反向+动态灯+遥测+RAM预览，诊断开关分别对照。保存/UF2/身份重启是明确维护例外；校准则检查其他来源持续服务。

可用逻辑分析仪/USB捕获/主机时间戳和外部运动参考。记录指针设置、装配、配置与游戏倍率；10～20Hz网页趋势仍不足以证明毫秒级性能。

## 8. 四类场景

| 场景 | 建议组合 | 重点 |
| --- | --- | --- |
| SDVX | 双旋钮+游戏实际键位，滑轨关 | 双路高速/急反向、方向和每圈倍率 |
| 音击 | 滑轨+键，两旋钮默认关闭（已确认） | 普通绝对输入和IO4分别检中心/范围/Side |
| In Falsus | 键+所选滑轨或X旋钮 | 绝对兼容、持续动作、快速反向和接管 |
| 普通多K | 不同K数键位，建议鼠标关 | 多键/长按/重复映射，避免无意鼠标移动 |

具体游戏版本/键位/倍率仍待提供。已有相对鼠标可用的说法不能证明新绝对滑轨报告兼容。
