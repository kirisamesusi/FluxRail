# 固件版本与 UF2 识别

文档版本：v1.1 · 更新：2026-10-04（北京时间）。对应 W05，供固件/公共层与 Web 后续窗口共同接手。本文件是识别记录、版本比较和发布维护的当前契约；历史文档中的手填预期版本、SHA-256 用户核对流程按本文修正。

正式整合固件从 0.10.0 起包含固定识别头。版本唯一维护入口是 firmware/FluxRail/src/common/FirmwareInfo.h 的 FLUXRAIL_FIRMWARE_VERSION；发布时修改这个值，再运行 python tests/integration/compile_firmware.py。不要分别修改网页或握手字符串。使用 SemVer major.minor.patch，可附预发布标识，最长 31 个 ASCII 字符。正式编译调用网页同一解析器验证实际 UF2 的身份、板型和版本，校验失败则构建失败。

## Flash 识别记录

记录为 88 字节、整数小端，字符串必须 NUL 终止且剩余空间填零。它位于真正的 Flash payload 中，不是附加到 UF2 文件末尾，刷写后 hello 读取同一记录。volatile 指针保留整个记录，避免 LTO/链接垃圾回收删掉未直接使用的字段；正式 UF2 检查验证恰好一个记录。记录未改变 USB 接口、CDC 协议版本、GPIO 或 Flash 配置布局。

| 偏移 | 长度 | 字段 | 值 |
| --- | --- | --- | --- |
| 0 | 16 | magic | FLUXRAIL-FW-V1，补零 |
| 16 | 4 | format | 1 |
| 20 | 32 | board | fluxrail-rp2040-4mib，补零 |
| 52 | 32 | version | FLUXRAIL_FIRMWARE_VERSION，补零 |
| 84 | 4 | end_magic | 0x46525746 |

hello 保留 firmware_version，新增 firmware_id、firmware_board、firmware_metadata_format，分别返回上述 magic、board、format。Web 仍兼容旧 hello；没有新字段时标注“旧固件未提供识别头”，若旧版本号符合 SemVer（如 0.9.0-integrated-software）仍可与新版 UF2 比较。

## 网页行为

固件更新主区显示当前设备版本；连接/断开/重新握手都会更新，不将上次连接或模拟版本作为当前硬件版本。选择 UF2 在本地验证已有结构、RP2040 family、块序号、地址重叠与程序区边界，然后按 Flash 地址重排有效 payload，读取识别头。允许合法乱序和跨连续数据块的识别头，不能跨 Flash 地址空洞，也不接受 UF2 padding 里的伪头。

- 无识别头、错误板型、损坏/重复识别头：提示“固件不对”。旧 UF2 没有识别头时无法识别，请选本项目新版正式整合固件。
- 文件与当前设备版本相同：提示“版本相同，无需更新”。
- 文件更新：提示“当前固件版本较低，可升级到所选版本”。
- 文件更旧：提示“所选固件版本过低，不建议降级”。版本按各段数值和 SemVer 预发布顺序比较，build metadata 不参与顺序。
- 未连接：显示文件版本，等待连接后自动比较。模拟会话明确提示不能比较硬件版本。
- 重连设备序号变化：提示无法确认原设备更新，重新选择文件后与当前设备比较。
- 无效文件或触发空文件检查时先清空旧候选，避免遗留“检查通过”结果；系统文件框关闭但不触发change时不保证清空，详见控制器规则。

不再要求用户手填预期版本或核对整个文件哈希。仍保留必要 UF2 格式与地址检查，文件选择不会发设备命令，也不会自动刷写。进入 ROM 与手动复制流程沿用原实现；复制后重新连接读回版本。

识别头用于辨别本项目格式、防止误选其他固件，不是密码学签名，不能证明文件未经第三方篡改或伪造。

## 控制器接线与状态规则

app.js 创建 FirmwareUpdate，把 uf2-result（实验室详情）、version-result（更新主区提示）、current-firmware（当前版本）传入。getConnection 仅在 client.alive 且 device.ready 时返回 hello，并传入 port.simulated；未完成读回或已断线返回 null。controls() 调用 render() 并在 busy 时禁用 uf2-file，文件 change 通过现有 action() 调用 check(file)。不要另开一个 hello 轮询或第二个串口客户端。

check() 先清空 candidate、expectedSerial、error，再异步读文件；成功候选是 validateUf2 返回的结果，文件版本来自 candidate.firmware.version。首个真实连接绑定 expectedSerial：离线选文件后连接也适用；断线保留已选文件但清除当前设备展示；重连同序号重新比较，换序号提示不能确认原设备更新，重新选文件才能绑定新设备。模拟不会绑定硬件序号。候选错误持续显示到下一次文件检查；取消选择只有触发 check(null) 时才会清空候选，关闭系统文件选择窗口而未触发 change 不保证清空。

assessFirmware 的状态包括 disconnected、simulation、different_device、wrong_device、unknown、same、older、newer。older、wrong_device、different_device、unknown 在主提示标记 error；文件解析错误统一显示“固件不对”。版本过低目前只是提示，不阻止用户手动复制 UF2，也不改变原进入 ROM 的能力/维护锁。same 仅表示版本优先级相同，build metadata 不参与比较；它不证明文件字节相同或已成功刷写。

旧设备 hello 未提供新身份字段时，保留原产品/板型验证，并允许合规 SemVer 参与比较。若字段已经提供，则必须匹配文件的 id/board/format；无法解析的当前版本显示 unknown，不猜测先后。不要为旧 UF2 添加绕过识别头的“仅凭版本通过”分支。

## 下次修改与发布步骤

### 只修改提示或版本排序

1. 先读本文、[Web交接](../handoffs/FluxRail_Web_开发与调整交接.md)和对应 uf2.js/controller.js。按该窗口的用户任务操作；本文不授权刷写。
2. 提示和连接状态改 controller.js/assessFirmware；排序改 compareVersions；识别头解析改 firmwareMetadata/validateUf2。保持现有身份校验、程序区边界、断连/模拟/换设备规则。
3. 在 web/ 运行 npm test；修改的 JS 另跑 node --check。更新对应 uf2.test.mjs 场景，浏览器刷新后实际选择正式 UF2 核对提示和控制台。网页状态使用已有模拟入口，模拟结果不算硬件版本确认。
4. 只有 JS/文案改动通常无需重编译固件；若解析格式改变，按下一节同步固件并重新构建。更新本文、Web交接、进度和本轮证据，不把旧测试数改成新结果。

### 发布新的固件版本

从根目录执行，已有工具链无需 npm install：

~~~powershell
cd C:/Users/admin/Documents/FluxRail
# 先编辑 FirmwareInfo.h 中的 FLUXRAIL_FIRMWARE_VERSION。
python tests/integration/run_protocol.py
node --test web/tests/uf2.test.mjs
python tests/integration/compile_firmware.py
python tests/integration/run_usb_descriptors.py
~~~

编译脚本已经调用 check_firmware_version.mjs。只核对已有产物时可单独运行 node tests/integration/check_firmware_version.mjs；输出 JSON 的 verified=true 仅证明当前文件解析及版本一致，不能替代重新编译、严格源审查或 USB/实板验收。该脚本用 Uint8Array 包装读取的 Buffer，跨工具运行时也应传入真正的 Uint8Array。

正式 UF2 为 [FluxRail.ino.uf2](../../../../tests/integration/build/arduino/FluxRail.ino.uf2)，相邻有 .elf。仅改版本也必须重新构建，不能只改网页或把旧 UF2 改名；module1/2/3 独立烟测 UF2 不能代替正式整合固件。全套软件验收仍用 python tests/integration/run_all.py，--skip-build 不包含正式构建。按改动范围决定是否需要全套；本次只跑了相关 Web、协议、构建和描述符验证，没有重新跑整个 run_all.py。

### 改识别格式或增加板型

这是固件/Web公共契约变化：先更新本文的格式、兼容和受影响模块，再同步 FirmwareInfo.h、ConfigProtocol.cpp、uf2.js 的 magic/format/board/offset/length/end_magic、控制器身份展示和测试 fixtures。当前解析器只接受格式1、FluxRail RP2040 4MiB，不会自动兼容格式2或另一块 RP2040 板。不要删 volatile 保留指针后只验证源码字符串；必须验证真正链接后的 UF2 恰好存在一个识别记录。

当前程序地址范围为 [0x10000000, 0x103FB000)，文件上限8MiB，块长度512字节、payload长度4字节对齐且最多476字节，family=0xE48BFF56。将来增加板型时按真实 Flash 分区更新边界，不因版本不同放宽公共配置保留区。若需求升级到防篡改/防伪，需要另行设计签名与信任验证；现有记录不能承担该保证。
