## 调度与双核建议

| 工作 | 起始目标 | 必须测量 |
| --- | --- | --- |
| 十二路按键采集 | 500us～1ms；PUSH独立判定 | 最大间隔、边沿延迟、误触 |
| 三霍尔完整向量 | 1ms | 时间戳、通道偏差、超期 |
| 每个MT6701 | 500us，2kHz | 最大有效间隔、CRC/场状态 |
| 各实时HID接口 | 请求1ms | 提交/完成节奏、公平性 |
| LED | 约60Hz | 传输/关中断时长 |
| 普通遥测 | 10～20Hz | 有界缓存、丢旧遥测计数 |

核心1：按键/PUSH、ADC、SSI、展开角度、霍尔定位、滤波、真实活动判定、异步校准。核心0：TinyUSB全部API、键/鼠标/IO4编码、最终来源路由、CDC有界解析、配置快照、灯帧、维护保存/UF2。PIO/DMA负责灯数据，不用长时间关中断的show路径阻塞USB。

跨核通道分开：

1. 十二路边沿可靠SPSC队列：source_id、down/up、sequence、timestamp、revision，并有状态恢复快照。
2. 运动记录：滑轨绝对位置/有效性/活动，旋钮展开角度与分时增量；有采样序号、时间、revision。诊断快照可覆盖旧遥测，不能用它替代快速往返记录。
3. 控制命令、不可变配置快照、校准任务及ACK。配置两核均应用后回复完成，不能只在核心0更新就声称成功。

有界队列必须统计溢出并定义恢复；volatile不能替代内存同步。优先共享SRAM的明确同步，避免占用RP2040核心暂停使用的硬件FIFO；软件FIFO只用经核对的非阻塞API。两核健康联合喂watchdog。Flash写入会暂停另一核，是明确维护阶段，不承诺维护中实时输入。

## 模块数据与单位

| 来源 | 公共输出 | 输出后端 |
| --- | --- | --- |
| BT1～10/P1/P2 | 独立状态及边沿，物理编号永久不变 | 普通keyboard/mouse_button；IO4 switch映射 |
| 三霍尔 | mm位置、归一化绝对位置p、质量、有效性、三raw/基线/响应 | 普通绝对鼠标X；IO4 ADC绝对轴 |
| 每个旋钮 | 14位原始角、展开圈数、分时增量、CRC/场状态、PUSH | 普通相对X或Y；IO4用途另验，不自动假定相对鼠标等价spinner |

滑轨p=(x-x_left)/(x_right-x_left)，区间0～1，反向后1-p；中心倍率/输出范围属于游戏配置。旋钮累计圈数turns及每圈HID counts保留小数，成功发送后扣除已提交整数部分。HID count不保证等于屏幕像素。

长失效/重连/改倍率后旋钮重建角度参考并清除历史；滑轨重新取得有效绝对位置后按恢复策略提交当前值，不能先转成相对差值。绝对位置USB忙时保留待提交最新有效坐标及采样统计；不能“累计绝对坐标”。高速动作在轮询之间的不可观测部分应如实记录。

## 来源路由

首版支持滑轨单用、旋钮单用、运动全关；双方启用后按真实操作接管，细化规则待定。活动检测在物理mm/角度域，不能因灵敏度改变接管门槛；噪声不接管。建议同周期起动固定优先级，持续同时动保留当前来源至静止滞回满足，网页显示当前来源及原因。

非当前旋钮仍采样，但不积累待发旧圈数；接管清旧来源积压并记录策略性丢弃。**滑轨接管应恢复固定绝对位置关系**，允许定位到磁铁当前对应位置；不能偷偷加偏移退回相对滑轨语义。接管是否立即跳到位置或短过渡需目标游戏测试，建议先明确呈现立即定位。

每路旋钮axis=X/Y可改，默认U4=X/U5=Y为建议。不同轴可在同一相对报告并发，不共享限速额度。两旋钮设同一轴时的相加/择一策略待定；滑轨与旋钮X不默认相加。Y独立，但绝对X报告可能改变Y，见下节。

## 普通USB报告设计需要先验证

建议NKRO键盘独立接口；相对鼠标用16位有符号X/Y并带三按钮状态。若用8位必须拆分并保留余量，不用clamp丢动作。

滑轨使用真正绝对HID语义。优先验证两个鼠标Report ID/集合与NKRO接口的组合；若需增加HID实例，本机默认CFG_TUD_HID=2必须有固定构建配置，不能误以为无限实例。报告ID、描述符与结构统一定义，不能由各模块各造一份。

**绝对鼠标涉及坐标配对，固件不知道PC当前鼠标Y。** 2026-10-04用户明确不使用主机助手，并选择Y从屏幕中点开始：ID2采用完整绝对XY，逻辑Y只在固件新启动初始化为16384/32767，此后Hall报告必须携带保留Y，不得反复归中。Hall启用时旋钮相对count在后端累积到该逻辑坐标，每count=32单位；关闭Hall继续相对XY。配置/维护/断连恢复不重新居中，其他鼠标改的系统Y无法自动跟随。实际按钮仍ID1唯一持有，ID2兼容按钮恒释放。须验证Windows启动、按钮交互、Y保持及目标游戏；不能把相对积分的Hall输出叫绝对定位。

全局mouse按钮状态只由公共映射器持有，绝对/相对运动与按钮边沿不能互相清零。多个鼠标集合若各携带按钮，须验证主机合并/释放语义，避免两个后端分别残留按住。

普通模式绝对兼容性不由以前“游戏支持相对鼠标”证明。先做描述符和目标游戏验证，再冻结报告方案；这是工程待验，不擅自修改用户需求。

## 动作与报告的公共边界

K01要求不同usage全键无冲；K05允许多个物理来源重复映射任意支持的同一键盘键，每次物理DOWN都重新触发该目标键；A仅为示例。十二路状态、可靠队列和公共映射器保留来源身份，USB后端统一发送。具体重复动作表只在[模块1](02_模块1_键盘与灯光.md)维护，保持规则/间隔见D01，重复鼠标见D02。

鼠标按钮状态只有一个所有者；运动来源切换不清按钮，静止也处理按钮边沿。修饰键状态统一计算，单usage的UP/DOWN重触发不释放其他键。普通usage与IO4功能bit分别映射，不能直接更换报告ID复用结构。

## 配置与持久化

| 域 | 建议字段 |
| --- | --- |
| identity/capabilities | FluxRail、板型、固件/协议、真实唯一序号、输入数量12/3/2、动作/报告能力、max_profiles |
| inputs.bindings[12] | source_id、action.type=keyboard/mouse_button/disabled；usage/modifiers或left/right/middle |
| leds | 开关、模式、全局/十键RGB、brightness_level0～100、速度/方向；灯链为硬件层 |
| indicator | 暂定实际25%，独立尺度与模板/IO4色优先策略待D06 |
| hall | enabled/invert、absolute_range、center_gain、响应预设；安装校准另存 |
| knobs[2] | enabled/axis/invert、gain、counts_per_turn_at_gain1、滤波、PUSH启用/防误触 |
| mouse.routing | 启用来源、接管策略/阈值 |
| profiles | 四预置+自定义，稳定profile_id、名称、槽内参数；active_profile |
| usb_mode | active NORMAL_NKRO/IO4、已保存启动模式；与游戏模板分开 |
| calibration | 三路基线/增益/极性、机械mm端点、中心/映射/噪声、有效性/版本 |
| meta | schema、RAM/两核applied/saved revision、dirty、长度/校验 |

PUSH动作统一在bindings，旋钮域引用P1/P2，不重复存两套动作。校准跨模板共享，同一安装上电不重新采无场基线。预览/切换只改RAM；显式save保存全部模板、全局校准、活动槽及启动USB模式一致快照。

自定义模板已确认可新增；建议支持create/copy/rename/delete；删除活动模板须原子切到另一个有效模板，不能留悬空id。容量上限及满容量行为明确。首次建立四预置；是否允许删除预置待UI规则决定，至少支持恢复预置并保留一套有效模板。

新magic/schema，不解释旧四霍尔EEPROM。建议可恢复双槽，但必须两个独立可擦除区域；两份放同一4KB擦除扇区不是断电保护。按实际4MiB程序/EEPROM/FS保留区确认分区和容量，不只扩大EEPROM数组。

热改键/切模板释放旧绑定、清旧revision事件，采样边界应用新快照/ACK后重建参考。保存维护暂停实时采集，完成重新获取参考。默认按键可用，未校准滑轨禁用并显示原因。

## 通信草案

普通模式USB CDC+Web Serial，建议逐行JSON：

- 请求protocol_version/id/op/payload；应答匹配id、ok/result/revision/dirty，错误code/message。
- 事件type/event/timestamp_us/sequence/payload；大数据分页。
- 单行起始上限4096字节，超长丢到换行并拒绝，不执行截断内容。
- 普通超时起始2s，长任务accepted+job_id再报进度/完成；超时先查询，不盲重试save/boot。
- set_config带expected_revision，拒绝旧页面覆盖新值。
- hello/get_config/set_config/save_config/restore_defaults、telemetry、calibration、diagnostics、enter_bootloader。
- list/get/create/copy/rename/delete/set_active_profile；导入scope=current/all/calibration，分段完成全包校验后原子应用。
- set_startup_usb_mode/get_usb_mode/reboot_to_saved_mode；IO4配置通道是否可用由能力声明，见专题。

进入UF2与身份冷切换分开；应答后断线是预期状态，重新握手才确认成功。协议不兼容停止写入。

## v0.5实施增补：模块1公共接入（2026-10-03）

用户已明确授权模块1窗口兼任公共集成。此增补先冻结模块1及公共实时基础的C++子集；原有业务需求不变，未冻结模块2/3算法参数、持久化schema或JSON协议。

- common/InputTypes.h：统一source_id=0..9为BT1..10、10/11为P1/P2；InputEdge含source_id/down/sequence/timestamp_us/revision/epoch。核心1是十二路流唯一生产者，成功入队才推进sequence；epoch隔离同revision下的断连/维护恢复。32位计数允许回绕。
- common/ConfigTypes.h：Binding、KeyboardConfig、ScanConfig、Rgb/LightingConfig为唯一类型定义；keyboard/lighting保留兼容别名，不复制结构。新增RuntimeConfig只持模块1运行子集与revision，不是假完整Profile，也不包含校准或Flash格式。
- realtime/SpscQueue：共享SRAM，release/acquire同步，满队列不覆盖；消费者peek并在模块接受后pop，模块背压时保留原边沿。仅一生产者/一消费者，禁止把其当多生产者通道。
- realtime/ConfigMailbox：核心0发布完整不可变ConfigCommand，核心1采样边界复制/校验，暂停旧流并用InputSnapshot回复revision/epoch/实际状态；核心0清旧事件、全释放/重建，确认恢复后才发Resume。不能提前宣称两核应用完成。
- 输入队列溢出触发恢复请求；旧epoch事件只丢弃并统计，不补历史。核心1暂停期间仍采样真实BT状态；PUSH由模块3统一生产者接入，当前尚无该模块时两位保持未提供状态，不读取其GPIO。
- 普通USB先接NKRO+三按钮；使用统一NormalHid与固定TinyUSB3.7.7启动适配，在硬件连接前注册接口，避免setup晚注册竞态。按键是modifiers8位+usage00..DF的224位位图；不使用六键报告。USB身份/绝对滑轨/相对旋钮/IO4专项分阶段验收，接口能力只声明已接入部分。

影响：模块3必须采用同一source_id与核心1合并流；模块4以后按统一Binding/亮度单位适配读回，不把本增补当新JSON协议；模块2无需更改位置算法。所有模块引用common头文件，公共编排与USB所有者唯一。实际C++路径与验证以docs/progress/模块1.md为准。

实施补充：模块3的核心1公共入口为App::submitFilteredPush(10/11,down,now_us)，当前未采样其GPIO；普通核心0配置入口为App::applyRuntimeConfig并等待appliedRevision。断连/USB传输失败允许新epoch替换正在进行的握手，正常配置忙时拒绝。已确认配置在新申请期间仍提供灯色；USB提交/诊断使用Arduino-Pico端口已有__usb_mutex，避免软件IRQ同核抢占。NormalHid当前只接相对鼠标三按钮，绝对X/IO4/Flash/CDC仍另阶段实现，不能对网页宣称这些能力已可用。

## v0.6实施增补：有界CDC运行配置协议（2026-10-03）

本阶段只扩展模块1运行子集：hello/get_config/get_status/set_config/restore_defaults。普通身份继续使用同一TinyUSB CDC，不增加USB栈或回调所有者。协议版本1，逐行JSON，单行最多4096字节；请求id为1..4294967295，payload为对象，set_config/restore_defaults带expected_revision。完整字段及样例见[CDC协议](../../../../firmware/FluxRail/src/protocol/CDC_PROTOCOL.md)。配置操作仅RAM预览，响应成功必须等两核ACK和释放/重建完成；能力明确不支持save_config、模板、滑轨/旋钮、IO4及升级。未保存配置重启丢失，saved_revision为null，不伪造Flash保存状态。

接收、发送和JSON结构都有固定上限；超长行丢到换行后报错，不执行截断部分。TX背压保留完整响应，停止读取下一请求；无Serial等待/阻塞flush或动态内存。断开CDC清掉半行和待发响应，已经接受的配置由App继续推进；重连先读回，不盲重试。

影响：模块4应按能力与scope=runtime_module1显示可用功能，字段从公共协议读回；模块2/3业务接口不变。已接入App，编译/ARM模拟通过；最终结果见docs/progress/模块1.md阶段7。

## 阶段10：模块1灯入口及维护完善

复用同一ConfigTypes/DeviceConfig/schema2和USB所有者，不新增公共配置字段或CDC命令。键灯本地渲染与IO4 GPIO覆盖统一经lighting::scaleKeyColor，遵守enabled及brightness_level0..100，最终pack仍限幅127/63。UsbBackend::applyHostLights现需传入已确认的LightingConfig（仅模块1公共调用点/测试受影响）；主机仅选择六ABC灯的RGB，不绕过用户开关/亮度，不修改保存颜色。

GP11工程策略：普通显示已确认模板indicator_color；首次无确认配置时保留默认白色，IO4在配置确认后优先身份品红(255,0,255)。indicator_enabled独立、实际25%不变。新建/恢复预置默认SDVX青(0,255,255)、ONGEKI橙(255,96,0)、IN FALSUS紫(128,0,255)、MULTI K绿(0,255,0)，复制保留来源颜色，自定义可改；已有保存/导入颜色与schema1迁移不重写。色表仍是D06工程建议，非用户最终色值确认。只改变新默认payload内容/CRC，字段布局/schema/协议版本不变，模块4读回既有indicator字段即可，模块2/3无接口影响。

Flash维护必须等LED !busy，faulted不能当DMA完成；超时按既有维护失败路径退出，不擦写。LED故障仍显示诊断，故障忙缓冲不释放/改写，恢复输出需受控重启。
