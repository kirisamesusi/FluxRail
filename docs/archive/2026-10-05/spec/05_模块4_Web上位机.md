# FluxRail 模块4：Web上位机

版本：v0.6 · 更新：2026-10-04。对应 **W01～W05**，同时呈现K/L/H/R/P/U相关设置。先读[开发交接入口](../handoffs/FluxRail_开发交接_窗口必读.md)、[公共协议](01_公共接口与集成约定.md)及三个输入模块。本文件保留需求规格，Web 已接入整合工程并提供本地单页。当前构建、修改和行为见 [Web 开发与调整交接](../handoffs/FluxRail_Web_开发与调整交接.md)；以下历史建议未落实部分不能当作已实现功能。

## 1. 职责与连接

一个页面控制全部功能，内部JS可分文件。USB HID承担实时输入；普通模式建议CDC+Web Serial配置/诊断，沿用旧项目路线。网页不计算实时位移，关闭网页后控制器仍工作。

建议Windows桌面Chrome/Edge，HTTPS或localhost；检查navigator.serial，用户手势选端口，按[Web Serial官方流程](https://developer.chrome.com/docs/capabilities/serial)处理授权/读写/断开。设备真值来自握手和读回，不以localStorage替代。

连接状态建议：未连接→选择端口→打开→握手→能力/配置读回→可编辑；另有协议不兼容、错误、校准、维护保存、进入UF2、身份重启和重连。核对FluxRail板型、协议、版本、唯一序号，避免向旧设备发新命令。

## 3. 按键录入与灯编辑

“监听电脑键盘”用于设置绑定；“设备按键测试”看板上状态。监听只作用于当前卡，取消/失焦退出，忽略长按重复；Esc本身需要录入时保留手动选择。系统保留键可能不可捕获，应有键位菜单。任意支持的同一键盘键都允许重复映射，A仅为示例；提示每次按下重触发且可能短暂中断原长按。鼠标按钮从菜单选，中键不是滚动。

手填单字母/数字/符号与标准键位录入区分，按统一action生成usage/modifiers；US布局转换为建议，需说明大写/Shift符号及主机布局影响（D03）。不宣称能输出任意中文或宏。

布局固定左BT8/7/6/5/9、右BT4/3/2/1/10。十项颜色按BT保存，改键只改标签。静态/呼吸/PRESS逐键色为首版计划，彩虹模式提示使用自动色但保留配色。

只显示一个键灯brightness_level滑块0～100，明确“100=灯珠最高50%”；协议/导入导出同一刻度。GP11实际25%单独说明，不混成滑块25。效果名单、默认RGB与模式颜色见D04/D06。

## 4. 模板、预览与保存

已确认四预置+自定义，设备保留已保存数据。每模板保存绑定、灯、运动来源/方向/灵敏度等；三路机械校准全局共享。音击两旋钮默认关闭。其余初始组合见[用户版](../handoffs/FluxRail_需求总览_用户版.md)，不得编造游戏默认键位。

建议新增/复制/改名/删除，稳定profile_id与设备容量；活动模板删除先切到有效模板，至少保留一套。预置能否删除、容量、启动默认值待D18/D19。不要把这些管理细节全部标成用户已选定。

预览只改RAM，滑块请求节流/合并，建议10～20次/秒起步并保证最后值发送。显式save保存完整快照，显示dirty、两核applied revision与saved revision及维护状态；不在每个input事件写Flash。

导入先校验schema/板型/数量/范围，再展示拟变更；分段接收整包成功后原子应用。旧四霍尔配置不直接解释。导出区分当前/全部模板和机械校准，附版本/设备标识；跨安装校准须提示不适用。

恢复默认建议分映射与灯、运动参数、清除校准。撤销读回已保存快照；普通重置不误删机械校准。未保存断连显示提示，自动保存不是已确认行为。

## 5. 校准与测试

滑轨引导包含移开磁铁基线、逐路差异/增益、全轨覆盖、真实端点和静止噪声；按设备job_id显示accepted/进度/完成/拒绝/取消。失败保留旧校准，校准任务只暂停滑轨输出；Flash保存另作维护阶段。保存后开机复用，不要求每次移磁铁重测。

旋钮两卡分别展示raw_turns、scaled_turns累计圈数与圈内箭头：gain1一圈→一圈，gain2→两圈，gain0.5→半圈。页面根据设备累计值恢复遥测间隙，不用低频相邻角度差推算圈数。诊断箭头圈数与主机像素/游戏倍率不同。

建议普通趋势10～20Hz；设备最大采样/有效间隔、CRC、deadline_miss和队列统计用于性能判断。网页平滑曲线不能证明1ms无漏采。

建议CSV：设备时间/序号、三路raw/响应/mm/p/质量、两角度/圈数/状态、当前来源、旋钮产生/提交/余量/策略丢弃、滑轨目标及采样/提交序号、间隔/CRC/缓存丢记录数。高速记录需有界缓存/预算，显示限额；优先丢旧遥测，不能堵实时输入。

可选“暂停指定来源HID，仅看状态”，退出重建参考；不默认加入可能在游戏误触的BOOT组合。

## 6. 通信与异常恢复

字段和命令以[公共契约](01_公共接口与集成约定.md)为准，不在本模块另造保存格式。匹配请求id，串行写队列、有界读缓冲；处理跨块半行、同块多行、超长行和格式错误。断线取消待处理请求，超时先查任务结果，避免盲重试save/boot。

set_config带expected_revision，旧页面冲突后读回。热改键/模板的设备端ACK需两核实际应用；页面显示真实结果，不把点击即当成功。协议不兼容停止写入，参数限制同时由设备执行。

IO4若无CDC，只显示离线/恢复说明，不能出现假的在线配置成功。显示实际身份、已保存启动身份、目标及重连结果。冷切换与进入UF2是不同操作，方案见[Arduino审核](09_IO4兼容与USB冷切换.md)，配置通道与返回入口待D22。

## 7. 固件更新

当前采用RP2040 ROM UF2手动复制；版本与文件识别行为见 [15号契约](15_固件版本与UF2识别.md)：

1. hello读回当前版本；选择UF2，本地验证结构/地址与FluxRail识别头/板型，自动提示同版、可升级、所选版本过低或固件不对，不要求手填版本或核对哈希。
2. 设备结束输入，应答后进入下载模式并断连。
3. 引导出现RPI-RP2后手动复制UF2。当前没有网页写盘或自动上传通道；File System Access是未来另行设计的建议，未实现。
4. 设备重新运行后握手读回版本并复核原设备序号，自动重新比较；版本读回不等于功能/实板验收通过。
5. 保留BOOT+RUN/插拔的ROM手动恢复路径。

Web Serial不能直接向原生ROM UF2串口上传；进入bootloader不是更新完成。根据[RP2040启动机制](https://datasheets.raspberrypi.com/rp2040/rp2040-datasheet.pdf)校验UF2结构/family/地址及板型，新板4MiB不得复用旧板UF2。无更新服务时不显示自动发现最新版；自定义bootloader/应用内升级需另行设计。
