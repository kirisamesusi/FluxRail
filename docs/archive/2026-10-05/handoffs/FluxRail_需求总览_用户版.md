# FluxRail 项目需求总览（用户版）

版本：v0.5 · 更新：2026-10-04（北京时间）。

这份文档汇总你要做的产品、四个模块的主需求、使用场景和还需要确定的地方。后续讨论可以直接报需求编号，例如“K05重复按键”或“H02滑轨绝对位置”。

**当前阶段：模块1～4已接入正式整合工程，固件版本与Web UF2识别已完成相关软件验证；实板/真实USB主机/游戏尚未验收。当前固件0.10.0，接手见[整合进度](../progress/模块整合.md)最新阶段和[版本契约](../spec/15_固件版本与UF2识别.md)，历史模块进度的“未接入”不代表当前状态。** 第三方参考已下载并整理，旧项目有用源码已保留。

## 1. 项目是什么

FluxRail是基于自绘RP2040主板的组合音游控制器，面向SDVX、音击、In Falsus和普通多K玩法：

- 十个独立按键，左右各五个。
- 三颗49E共同检测一个沿滑轨移动的磁铁。
- 两个MT6701磁旋钮，另有两路可配置PUSH输入。
- 十个按键灯及一个独立模式指示灯。
- 一个Web页面完成设置、测试、配置管理和固件更新引导。

**两条最重要的输入定义：滑轨是绝对位置；旋钮是相对移动。** 回到同一滑轨位置，应回到同一输出位置；旋钮持续多圈转动，应持续产生相对移动。

需求状态分为：**已确认**（你明确提出或确认）、**首版计划**（希望加入，或当前建议纳入）、**建议**（实现/默认选择）、**待定/待实测**。建议数值、算法与默认值不代表你已确认或已验证。

## 2. 四模块主需求

### 模块1：键盘与灯光

| 编号 | 主需求 | 状态 |
| --- | --- | --- |
| K01 | 十键全部无冲；两PUSH作为额外逻辑输入接入统一映射，启用后也不能造成六键截断 | 已确认；PUSH实物结构待完成 |
| K02 | 默认左侧ASDFV、右侧JKL;N，按固定BT编号保存；网页可随时修改 | 已确认 |
| K03 | 十二路都可映射字母、数字、符号、方向键、Space等键盘键，以及鼠标左/右/中键；支持禁用 | 已确认；中键指滚轮按压 |
| K04 | 网页监听电脑键盘录入，或手填单个字母、数字、符号；重复映射不禁止 | 已确认 |
| K05 | 多个物理键可重复映射任意支持的同一键盘键；每次物理按下都重新触发该键，允许短暂“该键松开→该键再按下”中断原长按 | 已确认；释放保持细节为实现建议 |
| L01 | 3～4种持续灯效，可关闭；保留最初要求的按下即亮；可调亮度与颜色 | 已确认；具体名单为建议 |
| L02 | 网页亮度0～100，拉到100只对应灯珠实际最高50%；所有输出路径由固件限制 | 已确认 |
| L03 | 十个按键可分别设置颜色，改键后颜色仍跟随物理按键 | 首版计划，你希望加入 |
| L04 | GP11独立指示灯暂定实际25%亮度，不同模式显示不同颜色 | 已确认方向及暂定亮度；颜色/优先规则待定 |

默认布局：

| 左侧从左到右 | 默认键 | 右侧从左到右 | 默认键 |
| --- | --- | --- | --- |
| BT8 | A | BT4 | J |
| BT7 | S | BT3 | K |
| BT6 | D | BT2 | L |
| BT5 | F | BT1 | ; |
| BT9 | V | BT10 | N |

建议持续灯效：常亮、呼吸、全键同步换色、彩虹流动。关闭为独立开关，按下即亮为额外反应模式。静态/呼吸/按下即亮支持全局或逐键颜色；彩虹自动配色时保留已保存的逐键颜色。具体效果名单仍可修改。

亮度例子：键灯滑块100＝实际50%，滑块50＝实际25%，滑块25＝实际12.5%。模式灯暂定“实际25%”，不等于键灯滑块25。

A只是同键映射的示例，规则同样适用于其他支持的键盘键，例如数字、Space、方向键等。重复映射不会提供两个完全独立的长按状态；采用你已允许的重触发。旧代码只合并同键状态，第二次按下不产生新边沿，**与FluxRail当前要求不同**。重复鼠标按钮是否也重触发仍待定，因为会中断拖拽。

### 模块2：三霍尔滑轨

| 编号 | 主需求 | 状态 |
| --- | --- | --- |
| H01 | 三颗49E共同检测一块磁铁；PCB位置左H1、中H2、右H3，H2居中 | 已确认 |
| H02 | 普通模式输出鼠标X绝对位置，IO4模式输出绝对轴位置 | 已确认 |
| H03 | 可以临时移开磁铁做校准；合格校准保存后，同一安装每次开机直接复用 | 已确认 |
| H04 | 静止稳、慢移顺滑、快扫和快速反向跟手；网页可调灵敏度、校准和基准测试 | 已确认目标；误差/延迟容差待实测 |

机械已知：滑轨100mm，左右限位柱各从端部向内7.5mm；两限位参考间距85mm。考虑滑块后的磁铁中心行程约80mm仍是估计，要组装后测。磁铁为10×5×3mm方形强磁，距传感器高度、极向和晃动尚未确定。

校准预计包含空磁场基线、三路差异、全行程覆盖、实际端点和静止噪声。换模板不重校准；换磁铁、高度或限位才需要重测。失败/取消校准保留原有效结果是工程建议。

“绝对位置灵敏度”需要进一步定义：建议用输出范围和中心倍率。大倍率可能提前到达边界，低倍率可能只覆盖中央区域，网页应说明。普通绝对X是否被目标游戏接收，以及怎样避免干扰Y旋钮，需要实际验证。

### 模块3：MT6701旋钮与PUSH

| 编号 | 主需求 | 状态 |
| --- | --- | --- |
| R01 | 两个旋钮输出相对鼠标移动，每路可在网页选择X或Y、方向及开关 | 已确认 |
| R02 | 两路独立灵敏度并保存；网页圆内箭头显示倍率后的旋转 | 已确认 |
| R03 | 双旋钮高速同时操作X/Y不互相限速，急反向顺滑、不丢有效运动 | 已确认目标；性能待实测 |
| R04 | 两PUSH可配置键盘/鼠标三按钮；暂不需要长按；旋转时防误触PUSH | 已确认 |
| R05 | 旋钮机械结构设计暂缓，磁环和按压结构完成后再调参验证 | 已确认安排 |

网页测试示例：倍率1时物理一圈＝箭头一圈；倍率2＝箭头两圈；倍率0.5＝箭头半圈。建议同时显示累计圈数，避免一圈后箭头方向相同、看不出转了几圈。

MT6701读取的是绝对角度，固件将角度变化转成相对鼠标运动。连续旋转不会按绝对坐标边界停住。磁环尺寸、充磁方式、气隙、同轴性和PUSH复位结构待完成；PUSH默认映射未指定，建议初始禁用。

| W05 | 固件带版本号和项目识别头；Web显示当前版本、识别UF2身份/板型并自动比较，提示同版/可升级/版本过低/固件不对；保留恢复引导，普通设置不依赖网页持续打开 | 2026-10-04已确认并完成相关软件实现；实板待验收 |

建议模板操作：新增、复制、改名、删除、恢复预置、导入导出；实际数量上限由设备存储确定并显示。建议区分“临时预览”和“保存到设备”，避免拖动滑块时不断写Flash。关闭网页后设备仍按已生效配置工作；临时预览未保存不承诺掉电保留。

网页“监听电脑键盘”用于录入绑定，“设备按键测试”用于看板上的输入状态，两者分开。鼠标动作从菜单选择。大写和需要Shift的符号受主机布局/Caps/输入法影响，默认字母标签A不代表强制输入大写字符。

当前更新流程：选择UF2并在网页本地识别/比较版本→进入RP2040的UF2下载模式→手动复制正确的新板UF2→设备重连后读回版本。文件选择不需手填预期版本或核对哈希；固定识别头缺失、损坏或板型不符提示固件不对，旧版无识别头UF2无法识别。当前固件版本0.10.0，技术格式和后续维护见 [版本与UF2契约](../spec/15_固件版本与UF2识别.md)。进入下载模式不等于升级完成，不能提供实际无上传通道的在线刷写按钮。

## 3. 使用场景和来源选择

| 模板 | 滑轨初始状态 | 旋钮初始状态 | 说明 |
| --- | --- | --- | --- |
| SDVX | 建议关闭 | 建议双路开启，分别X/Y | 两路同时快速操作是重点 |
| 音击 | 建议开启 | **默认两路关闭，已确认** | 普通绝对输入与IO4分别验证 |
| In Falsus | 与X旋钮择一，建议 | 按需，建议 | 自由配置和保存 |
| 普通多K | 建议关闭 | 建议关闭 | 以按键为主，可自由开启 |

各游戏真实默认键位、倍率和具体软件版本尚未提供，首版不编造官方键位。基础默认先使用ASDFV/JKL;N，之后你可修改。

**P01 已确认：** 操作旋钮时优先旋钮，操作滑轨时优先滑轨；网页能分别开启/关闭。是否默认两者同时开启、同一时刻两者一起操作如何接管仍待定，不能默认相加。Y旋钮应独立；两个旋钮设同一轴时的合并规则待定。

## 4. IO4与普通模式

**U01 已确认目标：** 研究把设备模拟成IO4，并支持与普通键盘鼠标身份切换。旧IO4实现你已测过不可用，不作为成功基础。

普通模式＝NKRO键盘＋绝对滑轨＋相对旋钮＋鼠标按钮。IO4＝按IO4协议报告按键和滑轨绝对轴；字符A/Space与IO4开关功能是不同映射，旋钮在音击默认关闭，IO4旋钮扩展另定。

**U02 建议方案：** 两种身份都采用TinyUSB，保存启动身份→重启→USB重新枚举冷切换；通常无需每次重刷固件。游戏模板热切换和USB身份冷切换是两种操作。

Arduino源码审核表明存在实现基础，但有启动时序、描述符重置、长字符串和回调约束，需要项目内固定的USB适配。**单固件双向切换、插上识别和目标IO4兼容尚未实板验证。** IO4若没有网页配置通道，必须有无需网页返回普通模式的入口。

## 5. 性能、保存与模块化

**Q01 已确认目标：** 音游激烈操作时稳定、顺滑、跟手、不吞有效按键/运动；不能只凭网页曲线平滑宣称无丢帧。

**Q02 建议实现：** 核心1负责输入采集和算法，核心0负责USB、配置和灯效；灯发送采用不会长时间阻塞USB的方式。建议起始采样：霍尔1kHz、每旋钮2kHz、按键0.5～1ms；这些数值还未验证，不是性能承诺。

**G01 已确认方向：** 在Arduino中分模块编写，最终一个FluxRail工程汇总。四业务模块外，USB、配置保存、跨核通信和调度由公共层管理。这个分工便于分别修改算法，不把代码堆进一个.ino。

建议显式维护保存、升级和USB身份切换时暂停输出，界面清楚提示；正常游戏期间不频繁擦写Flash。USB/采集故障要释放卡住的按钮，恢复时不要补发旧历史动作。

## 2026-10-04普通鼠标兼容决策

用户确认无需电脑辅助程序，选择Y启动从屏幕中点开始。固件发送标准绝对XY：滑轨决定X，Y从中点初始化后保留本设备Y旋钮调整；每次滑轨移动都保留该Y，不重新归中。滑轨启用时旋钮仍计算相对增量，但普通后端将其累积成绝对坐标，每count约1/1024屏幕跨度（默认1024counts/圈约一屏），原倍率继续可调；滑轨关闭时继续普通相对鼠标。保存、切模板、断连恢复不重置逻辑Y，新启动重新初始化。不能读取或保持其他鼠标后来改变的系统Y。此选择覆盖旧文档中尚待决定的坐标方案，Code10是否消除和游戏是否接受须新版实测。
