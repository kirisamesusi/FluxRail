## 目录职责

| 目录 | 内容 / Git策略 |
| --- | --- |
| `firmware/FluxRail/` | 唯一正式固件源码、模块README与CDC协议 |
| `web/` | 唯一当前Web源码、资源、软件测试和UI验证记录 |
| `docs/` | 当前模块交接、硬件/架构/验收状态、历史文档归档 |
| `tests/` | C++/Python/Node测试源码、金样和已冻结的实测/审核证据；各层`build/`忽略 |
| `dependencies/` | 固定TinyUSB生成脚本与适配说明；`generated/`由固定依赖生成或回滚包恢复 |
| `references/` | 原样保留的旧板与第三方来源选集、来源SHA及已有许可；不参与正式固件编译 |
| `backups/` | 完整Web/固件源码快照、固件回滚包和整理前文档ZIP，保留manifest及原字节 |
| `scripts/` | 新克隆准备等项目维护入口，不替代正式构建/测试 |

本机旧嵌套Git历史移至`backups/local-git-history/legacy-rp2040-zero.git`，仅本地保留；参考源码本身按普通文件跟踪，不建立子模块。构建缓存、node_modules、Python运行库、浏览器isolated-profile及会话、系统/编辑器临时状态不上传。没有删除本地生成物或历史实测证据。

`.gitattributes`保留原始字节，不在add/checkout时转换换行；源码、冻结证据和回滚包的SHA依赖这一点。不要批量重排历史JSON/源快照或更改旧清单。FluxRail原创代码及配套文档采用[MIT许可证](../LICENSE)；第三方文件及其备份继续使用自身版权头/许可，适用范围见[来源说明](../THIRD_PARTY_NOTICES.md)。

## 新电脑克隆与Web

```powershell
git clone --branch test https://github.com/kirisamesusi/FluxRail.git
cd FluxRail
node web/server.mjs
```

私有仓库需要当前GitHub账号具有访问权限。Node>=20，访问`http://localhost:4174`；Web不需npm install。运行Web软件测试：`npm --prefix web test`。先读[新窗口必读](FluxRail_开发交接_窗口必读.md)和[测试状态](测试状态与待验收.md)，不要把历史裸板记录当新硬件验收。

## 固件工具与首次编译基线

目前正式构建/ARM回归以Windows为已验证平台：Python3.12、Arduino CLI0.35.3、Arduino-Pico6.1.0、核心附带ARM GCC16.1.0和TinyUSB3.7.7。安装固定版本，不随意升级后引用旧结果；路径及`--cli/--core/--tools`覆盖方式见[运行发布](../RUN_INTEGRATED.md)和各测试README。

测试运行库安装到被Git忽略的本地目录：

```powershell
python -m pip install --target tests/module1/build/python-deps -r requirements-dev.txt
python scripts/prepare_checkout.py
python tests/integration/run_all.py
```

`prepare_checkout.py`校验仓库内最新回滚包全清单、旧源码与旧构建SHA，再为没有现有构建记录的新克隆恢复历史UF2/ELF/报告和私有依赖。它不编译、不上传、不修改设备，也不把历史结果写成新测试通过；已有构建记录不覆盖。只检查可用`--check-only`。

这样正式编译入口可以先保存旧固件/对应源码再构建新版本，不需跳过强制回滚。之后编译入口重新核对安装依赖SHA并生成私有适配；新编译交付文件带版本和UTC导出时间，见运行发布。生成物不入Git；需要对外提供UF2时以版本化文件单独交付，保留构建身份与测试边界。

## 日常修改与上传

当前开发与待验收使用`test`，普通推送用`git push origin test`；新窗口和新克隆从此分支继续。正式硬件与游戏验收完成后，再按用户指令建立/合并到`master`发布；目前不建立正式发布分支。`main`保留首次上传历史。

在各现行模块目录开发，按任务做相关检查，更新对应交接及实际证据。提交前检查`git status`和`git diff`，不要将浏览器profile、工具运行库、口令或错误固件加入版本控制。若远程已有提交，先fetch并审查差异，保留远程历史，不强制覆盖。

冻结证据里的本机COM号、用户名/绝对路径、设备序号是历史上下文，不是新电脑默认参数。原始记录保留其内容，未来工具必须从当前连接读取身份和配置。
