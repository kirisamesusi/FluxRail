# 模块 1：按键与灯光

更新：2026-10-05。本文按当前源码整理。模块软件和正式 App 接入已有模拟、编译与整机软件验证；按键实物延迟、灯珠色序/电平、真实游戏仍未验收。当前源码版本宏为 **0.10.2**；10 月 5 日测试板的设备 `hello` 也报告 **0.10.2**。用户手动刷写已确认，但上传过程和所刷 UF2 哈希没有直接观测；另有完整 0.10.2 回滚归档 UF2，SHA-256 为 `92991fa7e70e591fa16857ac09cd513eb337e6b6f0ca9cbe2824292379d9b479`。该测试板为 2 MiB，不能代替最终 4 MiB 板的 Flash 验收。10 月 4 日的 1 kHz 采样率实测只属于 0.10.1，不能转作 0.10.2 或按键扫描实测。

## 职责与硬件

模块负责十个低有效轴体的扫描消抖、BT1～BT10 与两个 PUSH 来源的动作映射/键鼠状态、键盘 NKRO 语义状态，以及十颗按键灯和独立模式灯的渲染与异步输出。HID 描述符、USB 发送、配置/模板/Flash、IO4 人格与跨核队列归公共 App/USB/配置层所有；不要在模块目录新建这些单例。

| 资源 | 当前定义 |
| --- | --- |
| BT1～BT10 | GP0～GP9，低有效，内部上拉；扫描周期 500 µs，默认按下/松开消抖各 1000 µs |
| 键灯 | GP10，WS2812 串行十灯；按物理 BT 顺序配置，输出时重排 |
| 模式灯 | GP11 独立输出，不是串行灯链的第十一颗 |
| PUSH | P1/P2 来源编号 10/11；硬件 GP19/GP20 由旋钮模块采集，动作配置与普通来源相同 |

BT 顺序与默认 HID usage 为 BT1～BT10：`; / L / K / J / F / D / S / A / V / N`，其中 A 为 usage `04` 且无 Shift。网页物理布局与配置数组顺序不同，处理绑定时按固定来源编号，不按页面左右顺序重排。键盘支持 HID usage `04..A4` 及修饰键 `E0..E7`；单字符录入解释 US ASCII，不处理输入法、主机键盘布局或字符串宏。鼠标按钮只有左/右/中三个全局状态；模块保留各物理来源，公共层合并按钮持有状态。

键灯颜色按 BT1～BT10 保存。灯链映射已经确认：BT9→BT8→BT7→BT6→BT5→BT4→BT3→BT2→BT1→BT10。代码当前 `kLedGrb=true`，但 RGB/GRB 尚无实板确认。用户亮度 0～100 映射到最多 0～50% 输出；GP11 单独固定 25% 上限并由配置独立启闭。灯效包括 Static、Breathing、ColorCycle、RainbowWave、Press 和关闭；预置灯色含工程默认值，见下文依赖。

## 当前实现与源码入口

- `keyboard/KeyScanner` 把原始十键电平转成稳定边沿；`KeyScannerRp2040` 负责 GP0～GP9 引脚读取。消抖和状态由扫描器维护，队列故障需要公共恢复流程。
- `keyboard/ActionMapper` 在核心 0 消费可靠边沿，按十二个来源映射键盘键或鼠标按钮。对同一键盘 usage 的重复物理 DOWN，会按队列发送目标 UP、再发送 DOWN；仅清理目标键并保留其他键/修饰键状态。鼠标按钮重复来源当前使用 OR 持有状态，不做鼠标重触发。
- `lighting/KeyLighting` 是纯渲染与亮度限幅；颜色数组使用 BT 顺序，动画不会改写用户保存的逐键颜色。`lighting/Ws2812OutputRp2040` 通过 PIO/DMA 异步输出，忙时不能覆盖当前 DMA 缓冲；DMA 超时故障时也不能复用故障缓冲。
- 正式接入由 `app/App.cpp` 调度：核心 1 `InputWorker` 扫描按键并拥有十二路边沿生产者；核心 0 将边沿交给 IO4 物理输出或 `ActionMapper`，服务映射器和唯一 USB HID 后端。核心 0 按约 60 Hz 渲染灯帧，仅使用 `ConfigCoordinator::appliedConfig()` 的已确认配置，再交公共 USB 主机灯仲裁及唯一 LED 输出。

关键文件：[`KeyScanner.cpp`](../../firmware/FluxRail/src/keyboard/KeyScanner.cpp)、[`KeyScannerRp2040.cpp`](../../firmware/FluxRail/src/keyboard/KeyScannerRp2040.cpp)、`keyboard/ActionMapper.{h,cpp}`、[`KeyboardTypes.h`](../../firmware/FluxRail/src/keyboard/KeyboardTypes.h)、[`KeyLighting.cpp`](../../firmware/FluxRail/src/lighting/KeyLighting.cpp)、`lighting/Ws2812OutputRp2040.{h,cpp}`、[`InputWorker.cpp`](../../firmware/FluxRail/src/realtime/InputWorker.cpp)、[`App.cpp`](../../firmware/FluxRail/src/app/App.cpp)。

## 接口、配置与协议边界

`KeyScanner` 产生 `source_id/down/timestamp_us/revision`，公共 `InputWorker` 为 BT 与 PUSH 边沿分配连续 sequence/epoch 并投递可靠 SPSC。核心 0 对公共队列只窥读队首；映射器背压时保留原事件重试，不能跳过或合并 UP/DOWN。边沿队列异常时通过暂停 ACK、清理旧流、释放输出、取真实来源状态并以新 epoch 恢复。不要用物理状态或 20 Hz 诊断快照代替可靠边沿队列。

绑定和灯配置属于唯一 `common::DeviceConfig::Profile::runtime` 投影，并通过现有完整 profile/schema2 配置、CDC 配置协议和保存协调器生效。PUSH 动作只在 `bindings[10/11]`，不会因绑定目标而增加灯或把 PRESS 状态映射到 PUSH。IO4 功能映射由公共配置提供；USB 人格、IO4 输入/灯命令仲裁及公共动作输出不属于此模块。普通鼠标按钮由公共路由器统一持有，绝对/相对运动报告不能清掉按钮状态。

灯输出的亮度限制在 `scaleKeyColor` 和最终 `packLightWords` 两处执行，主机 IO4 六键功能灯也须使用当前已生效 lighting 配置。GP11 使用实际生效模板/身份颜色：普通模式显示模板颜色，IO4 的优先身份色和预置色表属于当前软件策略；具体颜色是工程默认，仍可由后续用户产品决策调整。修改配置字段、默认值、颜色或 wire 表示前先核对公共 schema/协议及迁移约束，不能只改 Web 表单或本模块结构。

## 尚未实测与接手建议

尚无逐键实际延迟和真实游戏短 UP 识别结果；重复键测试只证明软件输出队列行为。尚无逐灯点亮对应、RGB/GRB、3.3 V 数据电平/灯珠型号验证，也没有全系统 USB/PIO 实测时序。IO4 主机灯命令与实际板上显示、正常游戏下 NKRO/鼠标状态也须在对应硬件和主机上验收。

接手时先读当前的 `FirmwareInfo.h` 与正式固件 README 确认源码版本、构建产物及板上版本各自的证据；再读 `ActionMapper`、`InputWorker`、`App::serviceCore0/serviceCore1` 和 `ConfigCoordinator`，沿已存在的唯一输入流定位问题。任何改变绑定或模板的回归应覆盖按住时热改、重复 usage、混合键鼠按钮、USB 忙/故障/断连恢复；灯改动应覆盖关闭及完整亮度边界，并保留 DMA busy/fault 的缓冲约束。实测按键/灯时记录 UF2 哈希、固件读回版本、板型、接线、主机与游戏版本；没有数据时保持“待测”。

## 2026-10-11 Web v2 对灯光的口径
网页灯效下拉里的“自定义”对应 `lighting.per_key=true`（此时 `mode` 写 `static`），逐键颜色生效、全局色不可编辑；其他灯效写 `per_key=false`。固件字段与渲染未改；没有逐键亮度字段，网页不提供。旧配置若同时是“动画 + per_key”，网页原值保留并提示，换灯效才清除。详见[对接指南](../Web_v2_设计实现与后端对接指南.md)。
